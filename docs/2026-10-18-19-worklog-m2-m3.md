## 4. M3 — 콘텐츠 엔진: 뉴스봇 + 화제 다이제스트 (2026-10-19)

### 4.1 설계 결정 5건
1. **worker 위치**: plan의 루트 `worker/` 대신 `backend/worker/` — db/redis/error-alert을 같은 package.json에서 재사용(의존성 갈라짐 방지). CLI `npm run worker:news`, `--loop` 상주 모드, 배치는 cron/launchd 권고
2. **봇 계정** = plan 표기 `role='bot'`의 재해석 — 새 role 컬럼 대신 기존 `is_agent`(0043) 사용. `ai_news_bot`, `ai_digest_bot`(email NULL, isAgent로 발행 게이트 우회). 두 username을 RESERVED_USERNAMES에 추가(사칭 방지)
3. **LLM**: OpenAI-호환 chat completions 추상화(`LLM_API_KEY`/`LLM_BASE_URL`/`LLM_MODEL`) — **키 없으면 결정적 stub**. 근거: 완료 기준 "사이클이 사람 개입 없이 돈다"가 네트워크·키 없는 로컬에서도 참이어야 함. 실패 시 status='failed' → 다음 사이클이 자기 복구
4. **중복 제거 3중**: URL UNIQUE(ON CONFLICT DO NOTHING) → 제목 유사도(정규화 + trigram Jaccard ≥ 0.85, 최근 30일 창) → 7일 지난 원문 스킵
5. **재시도 큐**: 사이클은 "방금 수집"이 아니라 status='new' 전체를 큐로 — 소스 장애·LLM 실패가 있어도 다음 날 같은 루틴이 복구

## 7. 오늘 세션에서의 핵심 배우기(반복 방지용)

4. comments는 폴리모픽(`target_type`, `target_id`) — post_id 컬럼 없음
5. ioredis NX dedup 서명: `set(key, val, 'EX', ttl, 'NX')` — 인자 자리 순서 조심
